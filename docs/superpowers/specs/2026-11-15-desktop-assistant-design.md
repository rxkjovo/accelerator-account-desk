# 迅雷游戏加速器桌面助手设计草案

日期：2026-11-15  
状态：用户已于 2026-11-15 授权开始基础桌面版实现；外部注册与兑换流程保持本人参与

## 目标与已确认流程

用户在 Windows 电脑上双击打开软件，按下面的流程完成一次任务：

1. 通过所选平台的官方入口注册或登录本人账号，首选 QQ，微博为新增候选渠道。
2. 使用该平台账号登录或创建迅雷游戏加速器账号。
3. 兑换加速时长，记录结果和到期时间。

会话已确认“更换 QQ 注册后可以兑换时长”这一前提。本方案据此规划，不重新论证兑换资格。每个账号实际到账多少时长、能否叠加，仍以当次兑换结果为准。

用户新增需求：注册好的账号在软件中保留并方便查看；记录与本人手机号的关联、会员到期及后续注销进度。会员使用 10～15 天为会话中的预计值，软件展示实际到期时间。

用户提供的微博截图显示：迅雷客户端内提供微博登录窗口，包含扫码、验证码登录和账号登录；验证码页面有“登录/注册”按钮，并提示未注册手机验证后自动登录。这证明页面提供了注册衔接入口；微博注册是否成功、新微博账号是否具有相同兑换资格尚未验证。

产品名称为“迅雷游戏加速器”，与“迅游加速器”区分。

## 交付方式选择

| 方式 | 特点 | 本项目选择 |
| --- | --- | --- |
| C# WPF 桌面程序 | 适合 Windows，便于启动、定位和衔接本机客户端；可以发布为 exe | 推荐 |
| Electron 桌面程序 | 适合网页界面和跨平台需求，通常占用更多安装空间及内存 | 备选 |

首版按 Windows 桌面 exe 设计。具体运行时和发布方式在实现前确认；尚未验证安装、打包和目标电脑兼容性。

## 主窗口

主窗口提供账号列表、手机号记录和当前任务的三步向导。

- 账号列表：平台类型（QQ / 微博）、账号标识、账号备注、关联手机号、当前阶段、兑换结果、到期时间和注销状态。
- 手机号记录：本人提供的手机号及备注、关联账号，以及官方界面实际提示的注册或注销限制。默认脱敏显示，支持本人展开查看。
- 当前任务：平台注册或登录、迅雷登录、时长兑换三个步骤，以及当前需要进行的操作。
- 常用操作：新建任务、继续任务、暂停、重试、打开对应官方入口。
- 兑换记录：口令、使用时间、返回结果、实际增加的时长。

软件重新打开后恢复本地任务进度。登录完成或兑换成功需要有明确的结果依据，不能把“已打开页面”当作完成。

## 三步操作

### 第一步：注册或登录平台账号

#### QQ 渠道

本轮已打开 QQ 官方注册网页：

https://ssl.zc.qq.com/v5/index/?lang=zhCN

页面当前显示手机号、短信验证码、昵称、QQ 密码，以及服务协议和隐私政策。

软件打开官方注册入口并显示当前任务。用户在官方界面完成注册所需的输入、验证和确认，成功后把新 QQ 号关联到当前任务。首版允许手动录入 QQ 号，避免依赖未经验证的成功页解析。

是否能够直接嵌入官方网页尚未验证。默认使用系统浏览器，主窗口保留任务进度。

#### 微博渠道

依据用户提供的截图，优先使用迅雷客户端中已有的微博官方登录窗口。窗口提供手机号加验证码的“登录/注册”入口，以及扫码和账号登录选项。

用户在官方界面完成输入、验证和所需确认。成功后记录微博账号标识和本人提供的关联手机号，并确认当前迅雷登录账号是否与之对应。微博渠道的完整注册、授权和兑换衔接仍需实际验证。

### 第二步：迅雷登录

软件启动或定位本机迅雷游戏加速器，并引导到所选平台的登录入口。用户在官方界面完成授权。

首次需要确定客户端安装位置。进入客户端后的窗口定位、登录状态识别能力，需要在实现时针对实际客户端版本验证。首版提供“已完成登录”的手动衔接方式；自动识别只有验证通过后才启用。

### 第三步：兑换时长

软件展示用户提供、已经验证有效的兑换码，提供复制和兑换记录功能。用户在官方兑换入口提交口令。

根据成功或失败提示记录结果；无法可靠识别时，由用户填写结果。记录实际到账时长和到期时间，不能使用预计赠送天数代替实际结果。

## 到期与注销记录

会员到期后，软件将会员状态显示为“已到期”，并提供查看账号及前往官方账号管理入口的操作。用户在 QQ 或微博官方界面发起、确认注销，软件保留本地历史记录以便查看。

第三方账号注销状态可记录为：未申请、已申请、官方提示等待中、已取消、已完成、待核实。只有用户提供的官方结果或经过验证的官方界面信息，才能确定完成状态。

分别记录注销申请时间、官方提示的等待期限、注销完成时间和结果来源。平台未提供具体日期时显示“等待期限未知”，不预设固定天数，也不自动推算手机号已经可以再次注册。

平台账号注销、手机号能否再次注册、迅雷账号解绑或注销、后续兑换资格分别记录。任何一项完成都不能自动推定其他项完成。历史账号注销后仍保留查询记录。

多手机号按普通联系人关联方式记录，便于用户查看自己各号码的账号与官方限制状态；流程遵守官方限制，不依据等待期安排自动轮换注册。首版按用户选择的账号逐次操作。

## 本地记录

每个任务记录：

- 任务编号与创建时间。
- 平台类型、QQ 号或微博账号标识，以及可选备注。
- 本人提供的关联手机号及备注。
- 当前阶段和最近一次操作结果。
- 已兑换口令、兑换时间、实际到账时长和到期时间。
- 平台账号注销状态、申请时间、官方提示的等待期限、完成时间，以及确认来源。
- 手机号相关限制的官方提示原文和记录时间；没有依据时保持未知。

初版使用本地 SQLite 保存任务和兑换记录。密码、验证码和授权凭据由官方界面处理；任务记录只保留继续流程所需的信息。

## 中断和失败

- 关闭软件、暂停或取消：保存当前阶段，重新打开后可继续。
- 浏览器或客户端未打开：提示具体原因，保留任务并提供重试入口。
- 页面要求验证或确认：显示需要本人完成的操作，等待完成后继续。
- 兑换失败：保留失败结果，由用户决定重试或更换口令；不自动循环提交。
- 无法判断成功：显示“待确认”，由用户补充结果。

## 首版验收

1. 在 Windows 上双击 exe 能打开主窗口。
2. 能创建任务，选择 QQ 或微博渠道，并按平台注册或登录、迅雷登录、时长兑换的顺序继续。
3. 能打开 QQ 官方入口、定位迅雷的微博官方登录入口，并衔接本机迅雷客户端；渠道支持状态有明确展示。
4. 完成后能查看平台账号、关联手机号、兑换结果和到期时间。
5. 中途关闭后，重新打开能恢复任务进度。
6. 页面未成功打开、登录未完成、兑换被拒绝时，不显示成功。
7. 会员到期、账号注销和手机号限制分别展示；官方等待期限未知时不显示虚构的可用日期。
8. 已注销账号的本地历史记录仍能查询。
