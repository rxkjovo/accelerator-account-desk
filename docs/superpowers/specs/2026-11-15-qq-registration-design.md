# QQ 注册向导与密码保存

用户已通过「开始！」授权实现上一轮确认的方案。

## 目标

在当前深色 WPF 软件内新增 QQ 注册向导：从已保存的本人手机号中选择一个号码，在 QQ 官方页面完成注册，将实际 QQ 号、关联手机号和可选密码保存回账号列表。已有数据、兑换规则及界面可读性继续保留。

## 流程与结果

用户进一步明确「只选择手机号、填写验证码，剩余步骤交给软件」。正常流程因此收敛为选择号码 →「开始注册 / 获取验证码」→ 输入验证码 →「同意协议并注册」。软件为本次注册自动生成昵称和独立的 16 位随机密码，填写固定 QQ 官方页面、按用户按钮请求验证码、在明确显示服务协议和隐私链接的提交按钮下协助提交。只有该用户动作可以勾选官方协议并发起注册；不是后台无提示提交。安全验证仍在官方页面由本人处理；不规避官方限制，不循环重发。

提交后短时检查固定 QQ 注册来源的可见成功文字及明确 QQ 号标签。明确成功时自动加密保存账号、关联手机号和密码。没有明确成功文字、匹配到多个号码、号码与所选手机号相同、来源不匹配等情况保持待确认并显示手动粘贴确认入口；不连续重复提交。未实测真实成功页，因此自动识别适配尚未验证，必须在交付时说明。手动补录时本人须确认已在官方页面成功注册。

账号初始阶段为已注册，会员到期保持未知，不自动推定迅雷登录或兑换成功。失败或关闭向导不建立账号；生成的资料在执行外部步骤前先保存为本机加密的待确认草稿，重开可找回，避免提交后网络错误导致密码丢失。已开始注册后锁定号码，防止结果关联到不同手机；重新开始需要明确用户动作。

## 密码

密码使用 Windows DPAPI CurrentUser 加密，绑定账号 ID，密文与账号在同一 SQLite 事务内保存。密码不进入账号模型、日志、备注、CSV 或可见列表。默认隐藏，查看或复制需要本人主动点击。没有已保存密码时可以补充保存；常规账号编辑不得擦除密码。

复制后提供提示，并在软件仍运行时限时清除仍等于所复制内容的剪贴板文本，不清除用户后来复制的内容。查看窗口关闭即清空可见内容。跨 Windows 用户或系统重装后可能无法解密；备份说明必须写明这个限制。

## 浏览器

使用 Microsoft.Web.WebView2 WPF。辅助填写仅允许 `https://ssl.zc.qq.com/v5/index/`；导航限腾讯 QQ 官方 HTTPS 域名。网页跳转不会扩展辅助填写范围。关闭自动密码保存和网页消息接口，不监听验证码、网络返回或密码输入，不修改证书验证。未知来源下载和意外权限请求拒绝；加载失败提供重试和系统浏览器官方入口，并保留手动保存结果路径。

## 验证与交付

验证原有 30 项检查，以及数据库升级、密文重开、账号与密码原子回滚、账号 ID 绑定、未知/歧义结果拒绝、资料脚本不触发短信或提交、向导人工确认后保存、密码默认隐藏与清理。使用独立测试数据和模拟页面，不执行真实注册、短信、安全验证或兑换。

发布 0.3.0 的自包含 Windows 文件夹和桌面快捷方式；说明实际验证边界。保留 0.2.0 与现有用户数据。
