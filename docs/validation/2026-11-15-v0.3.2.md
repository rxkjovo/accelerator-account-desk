# 0.3.2 兑换码入口与复制验证

用户在完成 QQ 注册、密码恢复和迅雷登录后指出：软件没有可直接复制使用的兑换码。本次在侧栏增加独立「兑换码」窗口，显示此前提供的截图中的 7 个口令，每条有复制按钮；支持保存本人另行输入的兑换码，供重开窗口后继续复制。

口令逐个从用户截图核对：`JSQPHB`、`XL888`、`XL7878`、`XL1314`、`XL6789`、`XL8989` 来自简书截图，`ws1997` 来自短视频截图。截图内容只作为资料，所有口令及截图声称的到账时长均标为未验证。没有联网检索、生成、兑换或将截图中宣称的时长写入账号。

截图口令随程序提供；添加的新码存入数据目录 `redemption-codes.json`，保留输入的大小写，忽略重复添加。空值、超长、空格或换行拒绝；损坏文件保留并阻止覆盖。单纯打开列表不建立用户文件，复制不修改账号、密码或兑换结果。保存通过临时文件原子替换。

新增 7 项行为检查先对未实现功能运行并得到 0/7，随后实现通过。最终检查使用强类型实际存储与原生 WPF 控件：默认口令和状态、重开保存、重复处理、无效输入、损坏文件保留、复制回调得到确切口令、表单添加后可复制并持久化。复制测试注入回调以避免覆盖用户剪贴板，没有模拟存储或数据库。另进行原生离屏界面渲染，检查按钮和文字可见。

完整 `scripts/test.ps1` 退出码 0，共 110 项：16 核心、12 应用逻辑、32 密码/草稿、16 注册会话、7 受拦截 WebView2 页面、9 原有表单、11 注册/密码表单、7 兑换码存储与表单。输出：`artifacts/v0.3.2-tests.log`；红绿证据：`artifacts/v0.3.2-codes-red.log`、`artifacts/v0.3.2-codes-green.log`；预览：`artifacts/visual-preview/redemption-codes.png`。

0.3.1 的成功页识别、10 位新密码、密码显示/复制和本次已有密码恢复均保留。0.3.2 使用独立发布目录，桌面入口指向最新版本；实际进程、程序集校验及数据保留结果另存 `artifacts/v0.3.2-final-manifest.json`。真实 QQ 注册、迅雷登录由用户完成；本次没有另发短信、注册、登录、兑换或修改官方密码。
